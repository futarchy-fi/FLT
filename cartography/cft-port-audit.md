# CFT external-repository port audit (hub-lsb1u.9.3)

Audit date: 2026-09-07.  Consumers are the five CFT seams and the PT local
duality proofs identified in `cft-reconciled.md`.  Evidence was taken from the
public branch aggregators, relevant source files, toolchain/manifests and project
pages.  Direct clones were unavailable in the execution sandbox, so this audit
does not claim an exact repository-wide `sorry` count or a local build.

## Verdict

| Repository | Sorry-free? | Statement fidelity for FLT consumers | Decision |
|---|---|---|---|
| `kbuzzard/ClassFieldTheory` | **Not verified; the gate fails.** There is no repository-wide certificate or exact census in this audit. A current downstream source audit reports unfinished upstream declarations, while the inspected `Cohomology/LocalInv.lean` slice itself is complete. | Useful finite-cyclic/Tate-cohomology and local-field substrate, but no exported local Tate-duality quartet, local-field Brauer invariant, global reciprocity, existence theorem, ray classes or prescribed-local-extension theorem | **REFERENCE / SELECTIVE PORT only** |
| `mariainesdff/LocalClassFieldTheory` | **No.** Its own public aggregator marks `AdjoinRoot` and `Ramification` as having sorries. | Foundational DVR/local-field work only; `LocalField.Unramified` is still disabled, `ClassFormation/` is not imported by the package aggregator, and there is no delivered reciprocity/existence theorem | **DO NOT PORT wholesale; use upstream Mathlib results** |

Neither repository presently discharges any FLT CFT seam end-to-end.  The prior
`cft-reconciled.md` marking of nodes 7, 8, 11, 12 and 5-partial as current port
candidates was too optimistic: they are **watch candidates**, not available
proof imports.

## 1. `kbuzzard/ClassFieldTheory`

Snapshot evidence: public `main`, retrieved 2026-09-07; toolchain
`leanprover/lean4:v4.33.0-rc1`, Mathlib `3bd2603b817feffa4cc0ce9f5d6bad4094ca746e`.
FLT is on v4.34.0-rc1 / Mathlib `bc06ce9f`, so even a selective port needs a pin
bump and API repair.

The public root imports exactly two `LocalCFT` files (`Continuity` and
`Teichmuller`).  Its strongest relevant implemented pieces are:

- finite cyclic Tate cohomology, Herbrand quotients, restriction,
  corestriction, inflation and inflation--restriction;
- nonarchimedean local-field, ramification, inertia, unramified-extension and
  unramified-cohomology infrastructure;
- `Cohomology/LocalInv.lean`, a proved equivalence
  `H^2(Z/nZ,Z) ~= Z/nZ` generated by the carry cocycle.

Statement-fidelity trap: that `localInv` is an **abstract finite-cyclic group
cohomology calculation**.  It is not the FLT boundary export
`H^2(G_{K_v},mu) ~= Q/Z`, and it supplies neither the limiting/class-formation
identification nor perfect local Tate pairings.  The root import list contains no
global-field, idele/ray-class, reciprocity, existence or Chebotarev layer.

Portable components and cost:

| FLT use | Component | Port vs prove |
|---|---|---|
| PT finite-group substrate | restriction/corestriction/inflation, Tate cohomology, Herbrand quotient | **Port S--M**; preferable to duplicating |
| Local-field substrate | ramification/inertia, unramified cohomology, valuation exact sequence | **Port M**, but audit each theorem's axioms first |
| CFT node 7 / PT local invariant | carry-cocycle `localInv` | **Port S** as a helper only; completing the local-field invariant remains **L--XL** |
| Local duality quartet | no matching export | **Prove/await L--XL** |
| Global existence/SW slice | absent | **Prove/await XL** |

## 2. `mariainesdff/LocalClassFieldTheory`

Snapshot evidence: public `master`, retrieved 2026-09-07; toolchain
`leanprover/lean4:v4.22.0-rc2`, Mathlib `81a4b04c3ae8a45c367ee1664e82b618694462c4`.
The twelve-release toolchain gap makes direct vendoring unattractive.

The package aggregator is unusually decisive evidence.  It labels the Basic,
DVR, equal-characteristic, ForMathlib and mixed-characteristic folders, but:

- explicitly annotates `DiscreteValuationRing.AdjoinRoot` and
  `DiscreteValuationRing.Ramification` with "It has sorrys";
- leaves `LocalField.Unramified` commented with `TODO: uncomment`;
- does not import the repository's `ClassFormation/` directory at all;
- describes the repository goal as formalizing local fields and **eventually**
  local class field theory.

Many `ForMathlib` items are already annotated with their Mathlib PR numbers.
The low-cost policy is to use the upstreamed Mathlib forms and copy only a
specific missing lemma after checking its modern replacement.  Porting the old
tree would reintroduce large API drift without supplying a consumer theorem.

## Recommendation

Do not add either project as an FLT dependency now.  Reuse the kbuzzard
finite-group/local-field pieces by selective, attributed ports only when a
consumer is ready, with a declaration-level `#print axioms` audit and a build on
the upstream pin as hard gates.  For the mariainesdff repository, prefer modern
Mathlib and treat the repository as historical design/reference material.  Keep
all five CFT seams stated locally so their conventions (arithmetic Frobenius,
duals and invariant normalization) do not drift while upstream work evolves.
